# V0.3 Iterative Orchestration

## Ziel
Ingo entwickelt sich vom reinen Koordinator zum validierenden Orchestrator.
Unklare Positionsdaten werden nicht direkt weitergeleitet, sondern iterativ mit Artika aufgeloest.

## Prinzip
- Bedeutung von Feldwerten wird nie vorausgesetzt.
- Pro Position werden mehrere Hypothesen gebildet.
- Hypothesen werden nacheinander gegen interne Daten geprueft.
- Jede Iteration erzeugt einen nachvollziehbaren Zwischenstand.

## Positionale Hypothesen
- customer_reference
- internal_item_no
- free_text_item_hint

## Iterationsende
- resolved: interne Artikelnummer eindeutig gefunden
- unresolved: keine plausible Aufloesung mehr oder weiterhin Mehrdeutigkeit

## Go-NoGo
- Go zu Erkan: Debitor unique und alle Positionen resolved
- NoGo: mindestens eine Position unresolved -> Human-in-the-Loop

## Datenmodell (rueckwaertskompatibel)
- positions[]
- artikaResult.positionChecks[]
- positionResolution[]
